# TripMesh P1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Continuous GPS tracking, stream-backed trip lists, working Share/Save.

**Architecture:** `MapShell` lifecycle owns a throttled position stream writing existing providers; one `watchTripsProvider` stream replaces all mock downcasts; Share via `share_plus`, Save via `shared_preferences`.

**Tech Stack:** Flutter, flutter_riverpod legacy `StateProvider`/`StreamProvider`, geolocator 13, share_plus 10, shared_preferences 2.2.

**Spec:** `docs/superpowers/specs/2026-10-04-tripmesh-p1-design.md`

## Global Constraints

- No backend: no Firebase config in checkout; mock-stream only, Firestore-swappable interface.
- Throttle exact: accept if (`dist > 15m` AND `dt > 5s`) OR `dt > 60s`; drop `accuracy > 50m`; ignore `< 10m` jumps when `speed < 2m/s`; `distanceFilter: 15` on the stream.
- Heading rule unchanged: `speed > 1` else null.
- Share text exact: `Join my TripMesh trip "<name>" with code <CODE>:\nnavora://join/<CODE>`.
- Prefs key exact: `tripmesh_saved_ids` (string list).
- Keep `ThemeMode.dark` M3, 48dp, Semantics; no new screens.

## Review Focus

- Background tracking must stop (battery): leaving Explore or backgrounding halts the stream.
- Permission revoked mid-stream stops cleanly with the existing SnackBar, no crash.
- Stream provider error shows retry, never a red screen.
- Save survives restart (prefs round-trip).
- Full suite stays green (existing timed-pump patterns for map widgets).
